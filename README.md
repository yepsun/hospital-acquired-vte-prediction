# Analysis code: ML versus Padua/IMPROVE for in-hospital VTE prediction

Code for: *Machine learning versus the Padua and IMPROVE scores for prediction of
radiologically confirmed in-hospital venous thromboembolism: development and
external validation* (JAMIA submission).

Development cohort: MIMIC-IV v3.1 (linked to MIMIC-IV-Note v2.2 and MIMIC-IV-ED v2.2),
413,406 adult admissions, 674 radiology-confirmed new in-hospital VTE events first
diagnosed >24 h after admission. External validation: independent tertiary hospital
in Beijing (data contain PHI and are **not** included or redistributable).

## Pipeline

Run in order from the repository root with `RES=results_vte` paths as described below.

| Step | Scripts | Purpose |
|---|---|---|
| 1. Cohort construction | `01_cohort/` | Build the primary cohort (retain prior-VTE admissions; exclude VTE imaged within 24 h of admission) and the 2×2 inclusion-criteria sensitivity cohorts |
| 2. Features | `02_features/` | 57 static admission-window features; 92 time-updated dynamic landmark features (48 h onward, 24 h refresh); `feature_sets_v2.json` defines the feature sets |
| 3. Models | `03_models/` | Static LR/XGBoost (`static/`), dynamic landmark LR/XGBoost (`dynamic/`), GRU sequence model (`gru/`; `48e` is the GPU/MPS re-run of the seed protocol) |
| 4. Evaluation | `04_evaluation/` | Calibration + decision curves, temporal/subgroup/strict-control/ED-vitals/service/prior-VTE analyses, threshold operating characteristics |
| 5. Figures | `05_figures/` | Cohort flow diagram (`make_fig1.py`, Mermaid source) and publication figures |
| 6. ICD-outcome sensitivity | `06_sensitivity_icd_outcome/` | ICD-code-based outcome definition (2×2 matrix, Table S7) |
| 7. Aggregated results | `07_results_summary/` | JSON summary outputs corresponding to manuscript tables/figures |

Outcome adjudication: events were ascertained from the full text of radiology
reports (CTPA for PE; lower-extremity duplex/CT venography for DVT) by independent
duplicate human adjudication with third-party resolution; the ascertainment
criteria, validation statistics, and pipeline details are described in the
manuscript Supplement (Supplemental Methods, Table S6). Label files are
patient-level derivatives of MIMIC-IV and are not redistributed; they are
regenerated by Step 1 from a credentialed local copy of the databases.

## Data requirements (not included)

- MIMIC-IV v3.1, MIMIC-IV-Note v2.2, MIMIC-IV-ED v2.2 — available from
  [PhysioNet](https://physionet.org/) under the PhysioNet Data Use Agreement
  (credentialed access; CITI training required).
- Expected local layout: the scripts read parquet datasets from
  `results_vte/` and `results_vte/ajm/new/data/` (cohort tables, landmark
  features, 12-hour bucket series) and write summary JSONs to
  `results_vte/ajm/new/output/`. Construct these inputs by running
  `01_cohort/` → `02_features/` on your local extract.
- External validation data (tertiary hospital, Beijing) contain protected
  health information and are unavailable; the export/featurization code for
  that cohort is not included.

## Reproducibility

- Models use fixed, untuned hyperparameters; evaluation uses three repetitions
  of 5-fold stratified cross-validation grouped by patient
  (StratifiedGroupKFold, seeds 42/43/44); inference uses patient-level cluster
  bootstrap (2,000 resamples per repeat).
- GRU training is CPU-compatible; `03_models/gru/48e_gru_mps_primary.py` runs
  the identical protocol on Apple-silicon GPU (MPS) and reproduces the seed-42
  results exactly.
- Aggregated JSON results in `07_results_summary/` were produced with Python
  3.11–3.14 (see `requirements.txt`); exact package versions used for the
  manuscript are documented in the Supplement.
